# 「一键破甲」功能风险评估备忘（2026-08-23）

> 结论先行：**确认有风险，不做。** 本文档记录网络核实的事实依据与决策过程，供后续参考，避免反复讨论。

## 一、什么是「破甲」（事实）

「破甲」在 AI 圈子（尤其 API 中转站 / 酒馆 SillyTavern 用户群）指 **越狱（jailbreak）**：

- 通过**越狱提示词、篡改 System Prompt** 等方式，绕过或削弱开源/闭源模型（Claude、GPT、DeepSeek、Gemini 等）的安全限制；
- 中转站再把这些「破甲」后的模型提供给用户调用；
- 常见用途：酒馆 NSFW 角色扮演（涩涩）、绕过内容审查、让模型执行被限制的任务；
- 市面上有配套工具：Codex/Claude Code/Cursor「一键破甲客户端」、破甲提示词包、本地代理注入改写引擎等，均以"绕过安全限制"为核心卖点。

> 注意区分：**「破甲」≠「分流」**。分流（模型→上游渠道路由/负载均衡）是正常的网络与渠道管理技术，TokUp 已实现；破甲是绕安全限制，两者无关。

## 二、风险核实（依据）

### 1. 真实运营事故（已发生，非假设）
- 2026-08-19 网络流传：有人用「破甲模型中转站」拿 AI **攻击中国政府网站**，事后该中转站被查，群主宣布「停止运营，后续警局出来就退款」，群被解散；
- 当天多个「破甲模型站」社群同时关停/炸群。

### 2. 监管层面
- 国家安全部近期发布安全提示，点名**非法「AI中转站」**：靠破解官方接口、共享违规账号运行，账号随时被封，**数据安全隐患大**；
- 「破甲模型」= 破解官方接口 + 削弱安全限制，属于被点名打击的范畴。

### 3. 上游封号风险（直接影响存量用户）
- 七牛云 / OpenAI / Anthropic / DeepSeek 等上游条款**明确禁止**越狱/绕过安全机制；
- 一旦检测到破甲行为，上游会**封掉整个渠道 Key**——不是封单个用户，是封 TokUp 全部走该渠道的调用；
- LINUX DO 社区实操经验明确：「中转站一般不让破甲，严重了会封号、收警告信」；
- TokUp 现有 400+ 用户、24h 600+ 次真实调用，为一个功能赌上整个上游渠道，**成本远大于收益**。

### 4. 产品层面
- 用户贴的截图里**并没有**「一键破甲」——那是另一个圈子（破甲工具）的东西；
- 破甲是灰色功能，做出来只能吸引高风险用户，同时劝退合规用户，伤害品牌。

## 三、为什么「大家好像都需要」
- 「大家都需要」的说法主要来自酒馆 NSFW 用户群与破甲工具营销，属于**特定圈子的需求**，不是主流 API 开发者需求；
- 主流需求是：稳定的模型、透明的价格、可靠的调用统计（如本次上线的「模型调用分析」）、低延迟——这些 TokUp 都在做。

## 四、决策
- **不做破甲功能**（含：不提供破甲提示词预设、不改系统提示词绕过限制、不做"可破甲模型"售卖）；
- 上游若提供合规的无限制模型（如部分开源模型），按正常模型接入即可，不额外宣传；
- 若未来监管明确合规的边界，再重新评估。

## 五、替代方向（合规且用户真正需要）
1. ✅ 模型调用分析（总数/TPM/RPM/消耗分布）—— 已上线
2. ✅ 分流视图（模型→上游路由透明）—— 已上线
